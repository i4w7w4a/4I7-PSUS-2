# Опыт 001 · передача карточки входа

**Оба исполнителя дали работающую команду первого входа в 4I7 PSUS 2.** При замене одного пункта сохранились название проекта, адрес памяти Хранителя, формат результата и вопрос о незаписанной зависимости. Для входа новичка в документации проекта используется [карточка A](answers/A.md). [Карточка B](answers/B.md) тоже воспроизводит исправленный способ входа.

## Что произошло

Сборщик подготовил [черновую карточку](brief.md) с общей точкой `oracle`. При проверке адресата обнаружилось, что так проверяется сохранённая работа сборщика. В [редакции 2](revision.md) первый читатель получает общую память, а к своей точке обращается при собственном возвращении. Положение `D-CARD-PERSONAL` в журнале заменило `D-CARD-SHARED`. [Поздняя заметка](note.md) с прежним предложением осталась в памяти в статусе `proposed`.

Сборщик сохранил checkpoint до поправки. После изменения проверка вернула `stale`, после сверки новая точка получила `fresh`. Это проверка механизма. Затем два отдельных исполнителя с пустой историей этой задачи вернули карточки для настоящей документации проекта. Условия приёмки записаны в коммите `b66dd78` до передачи. [Протокол](protocol.md)

Оба читателя получили одинаковое поручение и три исходных текста. A прочитал обычный журнал, B дополнительно получил состояния и связи этих же решений. Ответы сохранены до редактирования. Пакеты можно воссоздать из первых 33 ревизий журнала даже после продолжения проекта.

```sh
python3 experiments/001-entry/packet.py A
python3 experiments/001-entry/packet.py B
```

Независимый проверяющий оценил обе карточки по восьми критериям и повторно исполнил обе команды. Обе получили 8 из 8. В B путь к первой редакции проходит от `D-CARD-PERSONAL` по `supersedes` к `D-CARD-SHARED` и его ссылке на `S-BRIEF:v1`. По заранее записанному правилу равного результата в документацию вошла A.

Время включает диспетчеризацию, исполнение и задержку получения результата сборщиком. Разница в одну секунду здесь ничего не устанавливает о скорости читателя. Для этой карточки в структурированной памяти понадобилось 17 операций (ревизии 17–33) сверх подготовки трёх редакционных текстов. Сохранение личной точки и построение представлений выполнялись отдельно. Время человеческого ведения памяти в этом опыте не измерялось.

## Возврат к I

Для одного изменения способа входа обеих форм передачи оказалось достаточно. Связь с источником в карточке A видна прямо до обоих ID. Эта короткая задача оставляет открытым вопрос, помогает ли реестр, когда реальный потребитель решения обнаруживается только после передачи. Следующий проход откроет `R-REPEAT` при появлении другой задачи с поправкой. Для `R-DEPENDENCIES` нужен конкретный файл, исполнитель или процесс, чья зависимость от изменённого положения пропущена в памяти. Предел этого результата — одна задача, два исполнения, без случайного распределения.
