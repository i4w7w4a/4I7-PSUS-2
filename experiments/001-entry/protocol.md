# Проверка передачи карточки входа

26 ноября 2026. Это рабочая часть проекта: карточка предназначена для настоящего первого чтения памяти Хранителя. Условия конкретной карточки установил сборщик. Основу метода дал §7 отчёта о памяти. Цель автора и рабочая матрица действуют на уровне всего проекта.

Сначала сборщик оставляет первую версию команды, затем меняет только способ выбора личной точки. Два отдельных новых исполнителя получают по одному пакету без истории этого чата. В обоих пакетах одни и те же три редакционных источника в одинаковом порядке. Вариант A содержит обычный последовательный журнал. К варианту B приложена проекция этих же условий из действительной памяти v2 с состояниями и основаниями. Исполнителям даётся одна задача и одинаковый доступ: прочесть только свой пакет и вернуть карточку без записи в проект. Эталон и ответы другого исполнителя им не передаются. Сборщик проверит возвращённые команды в проекте.

## Условия приёмки до передачи

| Что проверяем | Что засчитывается |
| --- | --- |
| Имя | Заголовок содержит 4I7 PSUS 2 |
| Масштаб и идентичность | Команда собирает current P7 для точных ID и директории из первого документа |
| Форма результата | Одна запускаемая из корня команда через штатный Python CLI, явный JSON |
| Возврат к вопросу | Сохранены незаписанная зависимость и событие, которое открывает её проверку |
| Поправка | В команде первого входа отсутствует параметр участника. Возвращающийся читатель проверяет свою сохранённую точку |
| Поздний материал | Предложение не принято и не применяется |
| Основание | По карточке можно найти первую редакцию и поправку |
| Применимость | Код выхода 0, у пакета current, P7 и память с ожидаемым ID, поле проверки личной точки пустое |

Считаем сохранённые независимые условия (первые четыре строки), обращения к старому правилу при первом входе, выполнение остальных четырёх критериев. Замеряем размер пакетов в байтах, время от передачи до ответа по часам сборщика и число операций ведения реестра для этой карточки. Время включает работу сервиса. Одна пара без случайного распределения позволяет обнаружить конкретную ошибку, но для вывода о преимуществе способа передачи нужны повторения.

I возвращает владельцу проекта пригодную карточку при исполнении всех условий. Если обе карточки проходят, берём A как более раннюю по обозначению группы. При нарушении условий фиксируем отклонение до редактирования карточки.
